# 平台管理员与数据库升级

平台管理员是持久化的 `users.role=admin`，与组织的 owner/admin/member 分开。组织管理员不会自动成为平台管理员；平台管理员也不会自动获得其他账号的私人资料、会话或组织知识库权限。

## 升级已有数据库

先备份 PostgreSQL、上传/解析目录及向量数据，再在维护窗口停止旧 API/Worker 写入：

```powershell
uv sync --locked
.venv/Scripts/python.exe -m app.migrate
```

迁移在事务中执行，用数据库锁串行化升级。`0001_baseline` 固定升级前的表结构：已存在的表会核验列类型、空值约束、必要默认值、主键、唯一约束、外键、检查约束及索引；缺失的可选功能表会补建。结构不兼容时拒绝升级并回滚，不直接 stamp。`0002_platform_roles` 添加角色，历史账号全部默认普通用户。

空库同样执行上述命令；`python -m app.bootstrap --postgres` 也调用同一迁移链。应用启动不会自动升级数据库。可选的旧 bootstrap 命令仍用于显式初始化对应模块，不能代替版本迁移。

迁移暂不提供破坏性降级，避免删除角色及历史业务数据。需要回退时按已验证备份恢复数据库，并使用匹配的应用版本。

## 管理员注册

服务端设置 `REGISTRATION_ENABLED=true` 和非空 `ADMIN_INVITE_CODE` 后，注册表单显示的可选“管理员邀请码”可用于创建管理员。不填则创建普通用户；填写错误或服务端未配置时返回拒绝，不创建账号。邀请码可重复使用，修改服务端配置并重启即可轮换，现有管理员身份不受轮换影响。

邀请码不要提交 Git、粘贴到日志或用于普通账号密码。服务端不返回邀请码；注册请求不允许客户端直接提交 role。登录、刷新和 `/api/v2/auth/me` 均返回持久化角色；每次受保护操作重新检查当前用户状态与角色，旧 Token 不能保留已撤销的权限。

首次管理员也可通过注册创建。若要保留旧模型管理员权限，在核对 `.env` 的 `MODEL_ADMIN_USERNAMES` 后显式执行：

```powershell
.venv/Scripts/python.exe -m app.migrate --model-admins
```

该操作会将名单中全部已有且启用的用户提升为平台管理员，权限范围比旧模型管理更大。包含不存在或已停用账号时整批角色变更失败；重复执行幂等。运行时不再读取白名单授予权限，迁移完成后可移除名单。

## 页面与 API

- 管理员侧边栏新增“管理”，进入 `/admin`；普通用户直接访问会返回问答页。
- `GET /api/v2/admin/overview` 仅平台管理员可访问，返回功能开关及入库执行方式。这里是配置快照，不代表外部服务已经通过连通性验证。
- 已启用的模型中心、组织共享提供实际导航；未实现功能不展示可点击占位入口。
- 模型中心保留普通用户只读配置和个人统计；修改配置、目录探测、全局统计改为检查平台管理员角色。

真实环境的功能启用与独立 Worker 部署在下一阶段完成；仅注册管理员不会自动开启其他开关。
