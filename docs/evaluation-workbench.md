# 评测工作台

本功能提供持久数据集、任务、逐题结果及独立评测进程。评测调用真实的回答工作流与独立 `evaluator` 角色；执行完成和质量门禁通过是两个不同状态。固定企业语料与 80 题见 [资产说明](../evals/rag/synthetic_enterprise/README.md)。开发验收证据以[修复进度](replication-repair-progress.md)为准。

## 部署

先备份数据库、上传目录及配置，执行 `python -m app.migrate`。模型中心必须完成初始化并配置四个可用角色。评测要求以下开关同时开启：

```dotenv
MODEL_CENTER_ENABLED=true
CHAT_RUNS_ENABLED=true
EVALUATION_ENABLED=true
```

API、入库 Worker、Run Worker 和 Evaluation Worker 使用相同数据库及相关配置。分别启动 `python -m app.worker`、`python -m app.run_worker`、`python -m app.evaluation_worker`。完整 Compose 配置已包含独立的 `evaluation-worker`。容器共享上传/解析卷，每个 Worker 使用自己的心跳文件；不可将入库或 Run 心跳当作评测进程健康证明。`/health/ready` 和管理员部署预检会检查评测 Worker。

评测进程每实例处理一个任务，可部署多个实例竞争任务。默认每用户待处理上限为 8，租约为 45 秒；对应配置为 `EVALUATION_QUEUE_LIMIT`、`EVALUATION_LEASE_SECONDS`。数据库负责领取和写入隔离；已确认的生成检查点及审阅结果在接管时复用。外部调用发出后未确认就崩溃的情况无法承诺恰好一次调用，恢复尝试有上限。

## 使用

1. 管理员进入“评测”，导入满足 `WorkbenchDataset` 契约的 JSON。数据集按内容指纹去重、不可覆盖修改。各管理员只能查看自己导入的数据和创建的任务。
2. 从允许上传的业务文件入库语料，等待全部可检索。固定集仅上传 manifest 列出的 12 个文件；题目、参考答案和标签不得入库。
3. 选择数据集、开发/冻结分组和显式文档或共享库范围。共享库模式只使用选中库中的授权资料。标签只能描述来源锚点，不能赋予读取权限。
4. 先运行“基础检索”，完成后以其为对比基线运行“当前增强配置”。基础配置关闭父级上下文、三级合并、Grader 和 Rerank；两组均禁用外部联网和长期记忆，防止污染固定语料评测。
5. 运行前设定门禁阈值、最多失败题数及允许退化幅度。任务创建时冻结策略，运行后修改页面选项不会改写已有任务。
6. 查看实际回答、来源、逐事实审阅、调用记录和门禁判定。运行中可取消；刷新页面可恢复观察。取消不表示已产生的模型费用能够撤回。

创建任务 API 为 `POST /api/v2/evaluations/jobs`，需 UUID `Idempotency-Key`。同一请求重试使用同一个键；修改请求后使用新键。任务状态与逐题结果分别通过 `GET /jobs/{id}`、`GET /jobs/{id}/cases` 查询（以上相对于 `/api/v2/evaluations`）。API 只负责验证、冻结与入队，不在请求线程执行模型推理。

## 解释报告

同一数据集、分组、资料身份、索引身份及评测策略才允许建立基线关联。比较仍会检查逐指标实际评分群组；群组不一致或没有有效评分时，差值为不可比较，不补零。

标准事实覆盖衡量标签中的事实是否出现于回答；忠实度与引用支持来自评测模型基于实际合格证据的逐事实审阅。这属于模型审阅，不等于人工标注结论。必需指标没有完整评分覆盖时，门禁不能通过。无适用样本的指标标记为不适用。

Token 总量只有在所有调用都报告用量时才显示确定值，同时提供已报告用量和报告覆盖率。耗时包含单题在租约恢复期间的等待，不含任务排队时间。未建立真实 Gold Chunk 映射时不声称得到 MRR。没有真实完成的 A/B 报告时，不从脚本样例推断质量提升。

评测过程中管理员被降权、文档被撤权或索引身份改变，会阻止后续调用和结果发布。冻结参数不是复制模型服务或向量数据库；外部模型别名、索引内容仍可能由外部系统变化，需结合模型实际标识、语料哈希和实验时间解释复现范围。
