## 清理边界

- 新工作负载带本部署 namespace、Run 和随机 owner 标识。namespace 由数据库连接的后端、主机、端口、数据库名生成摘要，不含用户名、密码和查询选项；同一部署 Worker 使用一致连接身份。变更数据库地址别名时应先收回旧部署的工作负载，不能假设两种地址自动得到相同标识。
- 可信 Run Worker 启动就绪后、发布心跳前核查；运行循环每 30 秒再检查。只查本 namespace 且 managed=true 的容器，核验实际 ID、固定名称、Run UUID、owner 和创建时间。没有 namespace 的旧容器和其他部署不自动接管。
- 至少经过真实 90 秒宽限，覆盖 runner 最长 30 秒执行、传输及清理时间。持有 Run 行锁期间再次读取数据库时间与租约；running/cancelling 的有效租约阻止删除，其他 Worker 的续租/接管不能穿越该临界区。
- 删除使用完整不可变容器 ID。命令、输出、扫描数量与总时限均有界；不执行全局 prune，不删除镜像、数据库或数据卷。清理不发布产物、不改写未知工具回执，也不自动重新执行代码。默认关闭 Sandbox 时 Worker 指纹兼容；启用时治理协议升级为 2。

## 实际验证

在可信 Linux Worker 镜像中只读挂载当前应用源码，连接独立测试数据库和本地 Docker。先重跑真实 Run 的冻结 v1、3 份文件下载/安全预览/401/404，以及执行中取消和清理。随后启动独立的真实 Docker 驱动进程，观察工作负载运行后 SIGKILL 执行端，留下真实容器；等待实际 92 秒后验证：

1. 数据库有效租约阻止回收。
2. 显式使该测试租约过期后，容器被回收。
3. 同样年龄、另一 namespace 的测试容器仍存在，随后仅由测试 finally 清理它自己的精确 ID。
4. 非只读工具回执保持 started，没有冒充成功或触发重发。

真实 PostgreSQL 另验证清理持锁时其他连接的 NOWAIT 续租/接管锁请求失败，退出临界区后恢复可获取。最终没有本次测试工作负载残留，临时数据库由测试删除。
